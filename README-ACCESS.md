# 星羿工作台 · 访问控制（纯静态版）

> 部署地址（GitHub Pages）：`https://xytyymq.github.io/xingyi-workbench/`
> 方案：纯静态 + 非对称签名（ECDSA P-256）。**无需任何后端、无需配置 KV、不依赖第三方推送**。

## 核心机制

- 老板持**私钥**（仅存本机电脑，绝不外泄、绝不进仓库）
- 前端持**公钥**（内联在 `gate.js`，公开无害，无法用于伪造）
- 授权令牌 = 员工设备码 + 过期时间 + 用途，用私钥**签名**
- 前端用公钥**验签** + 校验设备匹配 + 校验未过期

**效果**：员工点开链接 → 被拦 → 微信发设备码给老板 → 老板生成专属链接回发 → 员工点开即进。
链接**仅限该员工那台设备**，转发给他人 / 换手机 / 换浏览器，直接拒绝。

## 老板怎么批新人（授权生成器）

1. 本机打开 `xy-token-gen.html`（已存你电脑，不进仓库）
2. 粘贴私钥（从 `xy-private-key.pem` 复制；可勾选"记住到本机浏览器"下次免粘贴）
3. 员工把他的「设备授权码」微信发你 → 粘贴到"员工设备授权码"
4. 填用途（如"教练-张三"）、有效天数（默认 365）
5. 点"生成授权链接" → 复制 → 微信发给员工

员工点链接自动进入，仅其设备有效。

## 更省事：临时绑定链接（无需员工回传设备码）

适合不想等员工发码的场景——**你生成一条限时链接，员工点一次自动绑他的手机**，以后永久进入。

1. 本机打开 `xy-token-gen.html`，粘贴私钥（勾"记住到本机"可免粘贴）
2. **勾选「📌 临时绑定链接」** → "员工设备授权码"自动置灰（不需要了）
3. 填：链接有效期（小时，默认 24）、授权时长（天，默认 365）、用途
4. 点"生成授权链接" → 把链接微信发给员工
5. 员工**点开链接一次**即自动绑定其手机并进入；以后这台设备免重复

**注意（转发窗口）**：
- 链接仅在生成后指定**小时内**可点击绑定；超时链接作废，需重发。
- 该窗口内若把链接转发给他人，对方点也能绑——所以链接私发微信、别群发。
- 员工若**清了浏览器缓存**，本机授权会丢 → 重发**同一条链接**（24h 内有效）让他再点一次即可，不用重新生成。

> 绑定链接不绑具体设备码，靠"本机设备码 + mac 完整性校验"固化授权：换设备/清缓存后旧授权失效，且无法被随意篡改本地记录。
> 旧版"设备令牌"链接（含设备码）依然有效，两种模式并存。

## 员工怎么进

**方式 A（设备令牌，需回传码）**
1. 打开工作台链接 → 被拦 → 看到「本设备授权码」
2. 点一下复制，微信发给老板
3. 收到老板发的授权链接 → 点开即进（本设备记住，下次免重复）

**方式 B（绑定链接，免回传码）**
1. 收到老板发的绑定链接 → 直接点开 → 自动绑定本机并进入
2. 以后这台设备免重复；清缓存则重发同一条链接再点一次

## 撤销某人 / 安全事件

- **单人失效**：让令牌过期即可（生成时设较短天数；已发的无法远程吊销，需等到期）
- **全面轮换**：若私钥疑似泄露，生成新密钥对 → 把新公钥替换 `gate.js` 内 `PUB_PEM` → 重新给所有人发链接。
  > 当前为单人小团队，远程实时吊销需后端（EdgeOne 方案），按需升级。

## 安全说明

- ✅ 公钥验证，没有私钥签不出合法令牌（攻击者拿不到私钥就伪造不了）
- ✅ 设备绑定，转发链接无效
- ✅ 有过期时间，泄露的旧链接会失效
- ⚠️ 私钥是你的最高权限，**绝不发给任何人、不在他人电脑打开生成器**
- ⚠️ 旧版 12 个授权码已作废，统一改用本签名流程

## 文件清单

- `gate.js` — 前端访问门（内联公钥、验签、设备绑定、跳转）
- `gate.html` — 授权页（设备码复制 + 粘贴授权进入 + 退出）
- `xy-token-gen.html` — 本机授权生成器（私钥本地签名，**不进仓库**）
- `xy-private-key.pem` — 私钥（**本机保存，不进仓库**）
- `README-ACCESS.md` — 本说明

## 旧地址可用性

GitHub Pages 项目站基址为 `/xingyi-workbench/`，`gate.js` 已按脚本地址自动推导跳转路径，
子目录页面（如 `match-platform/`）也能正确跳回根目录 `gate.html`。
